### 列の出所

- Rust 行数: `find impl -name '*.rs' | xargs cat | wc -l`（コメント・空行を含む）。作業ツリーの値。
- `#[test]` 数: `grep -rh '#\[test\]' impl --include='*.rs' | wc -l`。`#[tokio::test]` などは数えない。
- slt 総数 / m1 / m2: `find tests -name '*.slt'`（restart のフェーズ 15 ファイルを含む）、`tests/slt/m1`、`tests/slt/m2` 以下。
- spec 行数: `spec/design/*` と `spec/research/*` の `wc -l` 合計。
- slt 通過: `tests/run.sh --target yuzhu|pg` をファイルごとに流した成功数 / 総数（`--run-tests` 指定時のみ）。指定しなければ前回値を引き継ぎ、「(前回値)」を付ける。pg が起動していなければ「未計測」。
- restart 通過: `tests/run.sh --target pg --restart` の終了コード（OK / NG）。
- 未コミット: `git status --short`、`git diff HEAD --numstat`、未追跡ファイルの行数。`journal/` と `tools/journal-*.sh` は除く。
- ★行数: `grep -c '★' QUESTIONS.md`。説明文中の ★ も数えるため、★付き仮決めの件数より多い。
- 未承認★数: 人間が追認していない★付き仮決めの数。自動化せず手書き。
- 状態 ID: `git status --short` と `git diff HEAD` のハッシュ先頭 8 桁。同じ HEAD と同じ状態 ID なら行を追記しない（冪等）。

## 4. 指標の読み方（手書き）

- テスト先行の成否は、M2 統合後の **yuzhu 通過率**で測る。M2 の slt 24 ファイルと restart 6 シナリオは、PG17 では通っているが yuzhu では未実行（UPDATE / DELETE が未実装だったため。出所 `PROGRESS.md`）。
- 「M2 テストは yuzhu 未実行」の行は、実行したら同じ列に追記して比較する。見る点は、初回の通過率と、通るまでの修正回数。
- Rust 行数と `#[test]` 数は、増減の方向を見る指標で、品質の指標ではない。行数が増えて `#[test]` が増えないときは、テストなしで書かれた部分がある兆候。
- spec 行数が増えずコードだけが増えるときは、設計と実装の乖離（setbacks.md に書く）を疑う。
- ★行数の増減は、ディスク形式に関わる仮決めが増えているかを見る。未承認★が溜まるほど、M2 実装後の変更コストが上がる。

## 5. 欠測の扱い

- テストを走らせなかった行は「未実行」と書く。前回値を引き継いだ場合は「(前回値)」を付ける。引き継いだ値を、その行の時点の実測と読まない。
- pg が停止していて測れなかった場合は「未計測」。0 件通過と区別する。
- 手計測の行は、ラベルに「手計測」と書く。値が取れなかった欄は「不明」。
