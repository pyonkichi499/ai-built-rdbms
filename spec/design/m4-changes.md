# M4 契約からの変更記録

`m4/00-contracts.md` から変えた点・足した点。担当ごとに節を分けて追記する。

## P0-b（依存のない ★ スタブ一式と StorageStack 拡張）

- **スタブの置き場所**: 02 §5.4 の P0-b の表のとおり。`storage/btree/*`（B1・B2）、`storage/{index_store,sequence}.rs`、`ddl/*`、`copy/*`、`explain/*`、`deparse/*`、`catalog/{opclass,seq_params,naming,depend,check,names}.rs`、`types/{hash,cmp}.rs`。各 `mod` の宣言（`lib.rs`、`storage/mod.rs`、`catalog/mod.rs`、`types/mod.rs`）も P0-b が済ませたので、後続担当は自分のファイルの中だけを編集する。`storage/btree/testing.rs` は `#[cfg(test)]`。
- **`StorageStack` に `index: Arc<dyn IndexStore>`（`BtreeStore`）と `seq: Arc<dyn SequenceStore>`（`SequenceStoreImpl`）を追加**し、`Cluster::indexes()` / `Cluster::sequences()` を足した（02 の 00 への変更提案 14）。実体の B1・B2・Q1 が `StorageStack::new` の 2 行を置き換える（バッファプール・WAL が要るならそこで渡す）。
- **`recovery::dispatch` と `wal/dump.rs`**: `RmgrId::Btree` → `storage::btree::wal::{redo, describe}`、`RmgrId::Seq` → `storage::sequence::{redo, describe}` の呼び出し行を置いた（持ち主の M3 担当への依頼分）。スタブの `redo` は以前の `Error::internal` から `0A000`（`B+Tree REDO is not supported yet` / `sequence REDO is not supported yet`）に変わった。`describe` は 06 §3.7・08 §3.6 の書式の最小実装（`BTREE_PAGES` のページごとの役割は B1 が足す。いまはブロック番号だけ）。
- **`ddl::execute` は `CREATE TABLE` / `DROP TABLE` も `table::{create_table, drop_table}` に振り分ける**（02 の表は「`Error::internal("executed by the session until C1 moves it")`」を `execute` の中に書く案。07 §4.7 の形に合わせて振り分けを先に置き、スタブの中身が同じエラーを返す）。session は C1 が移すまで従来どおり直接処理する。`DdlCtx` は 07 §4.7 の 2 フィールド（`in_transaction_block`、`interrupts`）を含み、`write_ctx` `create_file` `schedule_unlink` `mark_catalog_dirty` `notice` `check_interrupts` は 07 §4.7 のとおり本実装（C1 が使う補助）。`ddl::sequence` に 08 §5.4〜§5.6 と C-28 の関数（`create_sequence` `create_with_oid` `alter_sequence` `drop_sequence` `drop_owned_by_table` `restart_owned_by_table`）のスタブを置いた。
- **`ddl` のスタブのメッセージに位置（`with_span`）は付かない**: `BoundCreateIndex` などの Bound に span のフィールドがまだ無い（空の構造体）。C1・Q1 が Bound に span を足したら付ける。
- **`deparse` は 10 §4.1 の型（`DeparseMode` `DeparseOptions` `ColText` `ColumnNamer` `SubPlanLabel` `SubLinkRenderer` `DeparseCtx`）と `deparse_expr` / `deparse_list`**（`0A000` `deparse is not supported yet`、式の span つき）。02 §5.4 の表の `deparse_lexpr` / `deparse_bound` は置かない（10 が署名を確定し、E1 は `ColumnNamer` で C を切り替える）。
- **`explain::run(options: &ExplainOptions, plan: &PhysicalQuery, span: Span) -> Result<Vec<String>>`**（`QUERY PLAN` の行。`0A000` `EXPLAIN is not supported yet`、位置つき）。10 §3.1 の `resolve_options` は AST の `ExplainOption`（S1）が入ってから E1 が足す。
- **`copy`: 10 §5.3 の API の入口**。`copy::begin(&BoundCopy) -> Result<CopyIn>`、`CopyIn::{ncols, rows, check_freeze, push_data, finish}`（`push_data` の名前は 10 に無いので P0-b が付けた。O1 が変えてよい）。`copy::text` の `LineReader::{new, push, line_no}`・`split_fields(line, delim)`・`unescape`・`RawField::classify` は本実装（10 §5.4 の規則）。`LineReader::next_line` は O1 まで `0A000`。`split_fields` は 10 の署名の `null` / `default` の引数を取らず、分割だけをする（分類は `RawField::classify`）。
- **`types/hash.rs`**: `hash_datum` は `DistinctExec::key_of` と同じ正規化（整数は i64、浮動小数は f64 に広げて NaN と `-0` を正規化、`bpchar` は末尾の空白を無視、numeric は `Numeric` の `Hash`、日時は内部の整数）。`HashKey` の `Eq` は `cmp_datum == Equal`。
- **`catalog/opclass.rs`**: 型と空の `static`、検索関数は `None`。`CmpFn` は `types::CmpFn` の再公開（A が `types` に置いたため。00 §11.3 は `catalog/opclass.rs` で定義）。

## P0-c（executor を `PhysExpr`・`rewind` に。旧 planner とは `planner/legacy.rs` で接続）

- **`ExecCtx` の拡張・`ExecEnv`・`ExecCtx::new` は P0-a が先に置いていた**ので、P0-c は `EvalCtx.type_env`、`ExecCtx::eval_ctx()`（`EvalCtx<'a>` を返す。`&mut ExecCtx` の呼び出しと借用が衝突しない）、`ExecCtx.instr` / `ExecEnv.instr`（C-10: `ExecEnv` が `instr` を持つ。型は `Option<Rc<Instrumentation>>` / `Option<&Rc<..>>`）を足した。`Executor::rewind` は既定実装を削除して必須にし、`set_counters`（既定は何もしない。C-2）を足した。
- **`eval`**: `PhysExpr` と `&mut ExecCtx`（`eval`、`eval_pred`）、`EvalCtx` だけの `eval_const` / `eval_const_pred`、`pub(crate) eval_with_sub_row`（C-10 の名前）。評価器は `Env::{Full, Const}` と `sub: Option<&Row>` を持つ。旧 `eval_expr` / `eval_bool` は削除し、旧 planner の定数畳み込み用に `planner::legacy::eval_expr`（`BoundExpr` を `to_expr` で変換して `eval_const`）を置いた（P0-e で消す）。`apply_cast` は引数に `&TypeEnv` を取る。`InOut` は `io::{output_text_env, input_text_env}`、`CastMethod::Env` は `ctx.type_env` を渡す。`session_value` は `Result` を返し、`CURRENT_DATE` / `CURRENT_TIMESTAMP[(p)]` / `LOCALTIMESTAMP[(p)]` を `type_env.datetime.now`（トランザクション開始時刻）から `types::datetime::{current_date, current_timestamp, local_timestamp}` で作る。`DateTimeEnv` が無い文脈では `XX000`。
- **ノード**: 既存 11 ノードを `PhysExpr` に移し、02 §3.7.1 の表のとおり `rewind` を実装。`ResultExec` は `one_time_filter` を持つ。`SeqScanExec` は `filter` を走査中に評価し、`SeqScan` と `Filter` が `set_counters`（`removed_filter` を数える。+0.1 日）。`SortExec` は `cmp_with_nulls` を使い、行ごとに `ctx.mem.charge`、`rewind` で `reusable` なら読み直し、そうでなければ `release` して子を `rewind`。`compare_keys` は公開をやめた。`DistinctExec` は M1 のまま（`rewind` で集合を空にして子を `rewind`）。`check_interrupts` は C-27 に従う（葉は `next` ごと。`Filter` / `Sort` / `Distinct` / `Limit` は入力を 1 行読むたび。DML は入力 1 行ごと）。
- **`reusable` の判定は C-6 のとおり `free_params`**（`executor/build.rs`。`PhysicalPlan::exprs_with_width` / `children` で書き、`physical.rs` は変えていない）。`SubPlanDef` の `params` / `test` / `Hashed` のキー式と `free_params(def.plan)`（`def.params` の束縛を除く）を数え、`NestedLoopParam.params` の束縛を inner と `join_filter` から除く。`query = None`（`build(plan)`）で SubLink を含む木は「空でない」。`PhysicalPlan::uses_params()` は残してあるが executor は使わない。
- **`build`**: `build(plan)`、`build_query(&PhysicalQuery)`、`pub(crate) build_scoped(plan, &BuildEnv, rewindable)`。`BuildEnv` は今 `query` だけ（`instr` と `ExecIdCursor`、`build_instrumented`、`Instrumented` は E1）。`rewindable` は P0-c のノードは使わない（X1〜X3 のノードが使う）。`Limit` の定数部分式の先行評価（`collect_constants`）は `PhysExpr` に移した。★ スタブの 12 ファイルの `build` は `pub(in crate::executor)`（02 の `pub(super)` では `executor::build` から見えない）。`NestedLoopJoin` と `NestedLoopParam` は同じ `nested_loop::build`。`UnsupportedExec` の `next` / `rewind` は `0A000 <ノード名> is not supported yet`。
- **DML**: `InsertExec::with_returning`、`UpdateExec::new(rel, table_name, input, n_user_cols, assigned, checks, not_null, returning)`、`DeleteExec::with_returning(rel, input, n_user_cols, returning)`。`SelfModified { cmax == w.cid }` は飛ばして RETURNING も出さない。DML の `rewind` は `XX000`。`executor/dml.rs`: `insert_with_indexes` / `update_with_indexes`（`rel.indexes` が空でなければ、ヒープに触る前に `0A000 B+Tree indexes are not supported yet`。X3 が索引の維持を足す）、`RowBuilder`、`RowChecker`（名前のバイト順に整列。NOT NULL に `s` / `t` / `c`、CHECK に `s` / `t` / `n` を付ける。05 §7.4）、`failing_row_detail(table, row, env)`（M2 の `failing_row` の後継）。`unique_violation_detail` は X3。
- **`executor/agg.rs`**: 05 の署名のスタブ（`AggState::{new(kind), transition, result, heap_bytes}`、`AggSet::{new, new_group, base_bytes, accumulate, finish}`、`AggGroup`）。`aggregate functions are not supported yet`。**`executor/subplan.rs`**: `SubPlanStates::take(id, query)` / `put_back(id, exec, started)`（05 §3.3。未構築なら `build_scoped(.., rewindable = true)`）を足した。`eval_sublink` はスタブのまま（`subqueries are not supported yet`）。**`executor/instrument.rs`**: `Instrumentation`（`new` / `finish` / `node` / `get` / `add_removed`）と `NodeCounters`（`Cell` のフィールド。`end_loop`）。**`executor/seq.rs`** は空。
- **`planner/legacy.rs`**: `to_expr`、`to_physical`、`to_query(plan, columns) -> Result<PhysicalQuery>`（02 の `-> PhysicalQuery` から変更。デバッグビルドで毎回 `validate`（P1〜P11）を通し、違反は `XX000`）、`to_physical_query`、`eval_expr`、`build_old`（テスト用）。旧 `Update` は入力の上に `Project[@0..@n-1, @n, 代入式…]` を足し、`assigned = (列, n + 1 + k)`。`Default(None)` は `rel.desc.attrs` の型の型つき NULL。旧 `SeqScan` の `filter` は `None`。
- **`session.rs`**: `planner::plan` → `legacy::to_physical_query(&plan, 出力列)` → `executor::build_query` → `ExecCtx::new(ExecEnv::without_indexes(..))`。`ExecEnv.indexes` は `NoIndexStore`（`cluster.indexes()` への配線は X3 / C1）。`type_env` は `TypeEnv::default()`（S が `Settings::type_env` に差し替える）。
- **テストの足場**（`executor/nodes/test_util.rs`。`#[cfg(test)]`）: `FakeStore`（M1〜M3 から移動）、`Fixture`（`new` / `with_params(n)` / `with_query(q)` / `ctx()` / `run`。`query`・`mem_limit` を差し替えられる）、`drain`、`CountingExec`（読み込みと `rewind` の回数）。X3 が `FakeIndexStore` を追記する。`eval::tests` の `col` / `lit` / `op` / `int` / `text` / `null` は `PhysExpr` を作る（`param` を足した）。旧 `BoundExpr` を作るヘルパは `eval::tests::bound`（旧 planner のテストが使う。P0-e で消す）。
- **他担当の範囲を触った点**（最小）: `planner/mod.rs` のインポート 1 行（`eval_expr` を `legacy` から）とテスト 2 モジュールのインポート・`malformed_input_rows_are_internal_errors` の `DeleteExec::new` の引数（`n_user_cols` を足し、`PhysExpr` ヘルパを使う）。
- **未実装・未検証**: `eval_sublink`（X1）、集約（X2）、索引の維持（X3）、`Instrumented` / `build_instrumented`（E1）。`EXPLAIN` の `Rows Removed by Filter` の描画は E1。release ビルドでは `validate` は走らない（`cfg(debug_assertions)`）。

## P0-d（analyzer を `Var` と `BoundQuery` に。旧 planner とは `planner/legacy.rs` で接続）

- **新しい Bound は `analyzer::query`、旧 Bound は `analyzer::bound` のまま共存**（P0-a の置き方どおり）。`analyze` は `query::BoundStatement`（`Select(Box<BoundQuery>)`、`Insert`、`Update`、`Delete`、`Ddl(BoundDdl)`、`Checkpoint`）を返す。`analyzer::BoundStatement` などの名前は P0-e まで旧型を指す。`CreateTable` / `DropTable` は `Ddl(BoundDdl::CreateTable / DropTable)`。デバッグビルドでは `analyze` の出力に `BoundStatement::validate`（B1〜B11）を通す。
- **`analyze_column_default` / `analyze_table_checks` は旧 `BoundExpr` / `BoundCheck` を返したまま**（`deparse/stored.rs` の `legacy` モジュールがそれを `Var` 版に写しているため。他担当の範囲）。新しい型を返す `analyze_column_default_bound` / `analyze_table_checks_bound` を足した。`deparse::stored` が新しい型に移ったら、旧名を新しい版に置き換えて `legacy::{expr_to_old, checks_to_old}` を消す。
- **`Scope` → `ScopeStack`**（`analyzer/scope.rs`）。フレーム（`ScopeFrame { rels }`、各 `ScopeRel` が `RteId` を持つ）の列で、末尾が現在のレベル。`levels_up` はフレームを数える（11 の C-3）。外側のフレームの探索・曖昧な列名（`42702`）は実装済みで単体テストがあるが、P0 の解析では常に 1 フレーム。`scope::ExprKind` は `ParseExprKind` に改名（03 §3.3。変種は M3 までの 9 つだけで、`Having` などは N1・N2 が足す）。システム列は `Var::system(rte, ..)`。旧 `used_system` は無く、`planner::legacy::from_bound` が `Var` から集める。
- **出力列の由来（`OutputColumn.table_oid` / `attnum`）はシステム列を `(表の OID, 負の attnum)` にした**（03 §3.2.10、PostgreSQL と同じ）。M3 までは `(0, 0)` だった（`SELECT ctid` の RowDescription が変わる）。
- **スタブの署名は 03 §3.4**（02 §5.4 の表と食い違う箇所は 03 に従った。D11-1）: `from::analyze_from_clause(&self, from, fb: &mut FromBuilder, env: &QueryEnv)`、`agg::analyze_agg_call(&self, e, cx) -> Result<Option<BoundExpr>>`、`agg::check_grouping`、`select::{resolve_group_by, resolve_distinct_on}`（どこからも呼ばれない署名だけのスタブ）、`sublink::analyze_sublink`、`setop::analyze_set_operation(&self, body, q, env)`、`cte::{analyze_with, find_cte, is_future_cte}`（`CteScope` / `CteEntry` / `CteLookup` / `WithResult` も置いた）。**02 の `analyze_grouping(s) -> Result<GroupingInfo>`（空の構造体）も置いた**: `DISTINCT ON` → `GROUP BY` → `HAVING` の順に `0A000` を返し、`analyze_select` の先頭（FROM より前）で呼ぶ（M3 までの検査の順序・位置を保つため。N2 が 03 の `resolve_*` / `check_grouping` の呼び出しに置き換える）。`from.rs` は `find_cte` を呼ぶ（名前が 1 つだけの表名）。`QueryEnv`（`outer: Option<&ScopeStack>`、`ctes`、`resolve_unknowns`）と `FromBuilder { rtable, ns }` は `scope.rs`、`TargetList` は `select.rs`。`ExprCtx` は `{ scopes, kind, ctes: Option<..> }`（`ctes` は N3 が使う）。
- **`analyze_query(q, &QueryEnv)` の骨格（C-20）**: WITH（`analyze_with`）→ 本体の振り分け（`Select` / `Values` / `SetOp` → `analyze_set_operation` / `Nested`）。`Nested` は外枠・内側のどちらかが空なら 1 つにまとめる（外枠の WITH は内側の本体へ。両方に WITH があれば `0A000`）。`BoundQuery.ctes` は WITH の結果。`CteScope` は WITH がなくても 1 段作る。
- **VALUES**: 単独の VALUES は `BoundSetExpr::Values { rows, types }`（`order_by` は出力列の位置）。ORDER BY が出力列でない式（resjunk が要る）のときだけ、`RteKind::Values` を FROM に持つ `Select` で表す（`VALUES (1),(2) ORDER BY column1 + 1`。M3 までは通っていたので維持した）。
- **`INSERT ... SELECT` で本体が VALUES のとき**（`INSERT INTO t (b) (VALUES (1))`）は、型変換を `coercions`（`Var { rte: 0, col: i }`）で問い合わせの上に置く（M3 までは VALUES の `targets` の中で変換していた）。エラーの位置は問い合わせの位置のまま。
- **DML**: `BoundUpdate` / `BoundDelete` は `rtable[0]` が対象表（別名があればそれが `refname`）、`from` は空。`BoundInsert` は `overriding: None`、`returning: None`。`RETURNING` / `UPDATE ... FROM` / `DELETE ... USING` は M3 のまま `0A000`（N1 の担当）。`BoundCreateTable` は `constraints` / `sequences` が空。
- **`analyzer/{ddl_constraint,ddl_index}.rs` のスタブ**: `ddl_constraint::{analyze_index_constraints, analyze_add_constraint}`（07 §6.9 の署名。`BoundIndexConstraint` は P0-a の型（`name: String`）のまま。07 §4.6 の `Option<String>` などは C1 が `query.rs` と一緒に直す）、`Analyzer::{analyze_create_index, analyze_drop_index, analyze_alter_table, analyze_truncate, analyze_vacuum}`（`ddl_index.rs`。`ALTER TABLE` は `BoundAlterTable { AddConstraint, Owner }` を返す）。どれも `0A000`、`analyze`（`mod.rs`）からはまだ呼ばない（M3 のとおり `this statement is not supported yet`）。`tests_{from,agg,sub}.rs` は空。`tests.rs` のヘルパ（`catalog` `run` `err` `create` `select` `names` `types`）は `pub(super)`。`select` は旧 `BoundSelect` と同じ読み方ができる `Sel` を返し、`BoundQuery` は `query` で取る。
- **`planner/legacy.rs`**: `from_bound(&query::BoundStatement) -> Result<analyzer::BoundStatement>`（`Var { rte: 0, col }` → `ColumnRef { index: col }`。システム列は出現順に `natts + 位置`、順序は旧アナライザの解決順＝出力列 → WHERE → resjunk、UPDATE は WHERE → SET）、`create_table_from_bound` / `drop_table_from_bound`、`expr_to_old` / `checks_to_old`。WITH・集合演算・集約・JOIN・`DISTINCT ON` は `0A000`。
- **`session.rs`**: `analyze` の結果が `Ddl(d)` なら `exec_ddl`（`CreateTable` / `DropTable` は従来の `exec_create_table` / `exec_drop_table`、それ以外は `ddl::execute(&mut DdlCtx { .. })`）。それ以外は `legacy::from_bound` で旧 Bound にして従来の経路。
- **未検証・未実装**: `analyze` を通らない経路（`ddl_index` などのスタブの呼び出し）は単体テストだけ。`ScopeStack` の複数フレームは `scope.rs` の単体テストだけ（解析からは使われない）。

## P0-e（planner を `build` → `rules` → `physicalize` に。旧経路・`legacy.rs`・旧 Bound を削除）

- **形**: `planner/{build,physicalize,rules/*,util,size,print,validate,index_select,explain_tree,check_const,simplify,tests}.rs`。署名は D11-1 により 04 の章に従った（02 §5.4 の `apply(q: LogicalQuery, env) -> Result<LogicalQuery>` ではなく 04 §3.3 の `RuleFn = fn(&mut LogicalQuery, &RuleCtx) -> Result<()>`、`rules::{run(q, env, trace), run_only}`、`PlanTrace` / `NoTrace` / `plan_traced`、`build::build_statement`、`PlanEnv`（`Clone + Copy`、`explain_verbose` つき）、`PlannerSettings`（`validate_plans` を含む。既定 `cfg!(debug_assertions)`））。各ルールの `apply` は恒等。`validate_plans` が真なら `build` の後・各ルールの後・`physicalize` の後に `validate`。
- **`analyzer::query` を `analyzer::bound` にした**（旧 `bound.rs` の旧型は削除。`OutputColumn` は `bound.rs` に定義）。`analyzer/mod.rs` に `pub use bound as query;` を残した（他担当の `analyzer::query::` の参照が残る間だけの別名。統合で `bound` に置き換えて消す）。`analyze_column_default` / `analyze_table_checks`（旧型）は削除し、`*_bound` を正とした。`deparse/stored.rs` の `legacy` モジュールを消し、`*_bound` を直接使う（`Cast.implicit` は analyzer が付けた値をそのまま使う。`deparse` のテストは通っている）。`executor::eval::tests::bound`（旧 `BoundExpr` のヘルパ）も削除。
